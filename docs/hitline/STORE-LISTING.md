**Detailed description**

```
Is your tracking working? Prove it in one panel.

Hitline shows which tracking fires on a page, where it goes, whether it respects consent and whether attribution survives the visit. One click gives a summary, DevTools gives the full picture, and one more click turns the findings into an audit PDF.

WHAT IT READS
- 50 platforms: analytics, ad pixels, session recording, CRM, tag managers, A/B testing tools and the dataLayer
- Your own services too: add a custom platform in Settings with a name and a part of its URL

IN THE POPUP
- The site you are on, updated live while the popup is open
- Platforms found on the page with their event counts, and the server-side GTM verdict
- The latest events, with their details on one click
- The top issues, and a short audit PDF

IN CHROME DEVTOOLS (press F12, open the Hitline tab)
- Events: every hit and every dataLayer push, newest first, with all parameters decoded, the account ID and the route (browser, server-side GTM or page). New events light up as they arrive
- GTM and sGTM: every tag with its trigger, consent checks and status, each dataLayer event with the tags that fired on it, and server-side GTM checked with four signals
- Checks: e-mail addresses sent to ad and analytics platforms, events sent twice, purchases without an order ID, events without a value
- Consent: Consent Mode v2 defaults and the visitor's choice, a timeline before and after the choice, and the GTM fix for each leak
- Attribution: UTM and gclid followed page by page, cross-domain breaks and unwanted referrals found, with the GA4 setting that fixes them
- Tracking plan: load your plan as CSV or JSON and see which events are missing or have wrong parameters
- Audit PDF: platforms and IDs, events, GTM tags, the consent timeline, the visit path, and every issue with why it matters and how to fix it

PRIVATE BY DESIGN
- No account, no server, no analytics inside the extension
- Everything is analyzed in your browser. Hitline makes no network requests of its own
- Only your settings (language, your domains, tracking plans, custom platforms) are saved, and only on your computer
- Minimal permissions: active tab, scripting, local storage and the DevTools panel. No access to all your sites
- Open source: https://github.com/shemistanisayev/getlineapps

Free, with no paid plan and no usage limit. Built by Shamistan Isayev, analytics and server-side tracking consultant. Need help fixing what Hitline finds? https://shamistanisayev.com
```

## Privacy practices tab

**Single purpose**

```
Hitline helps people check the analytics and advertising tracking on a website: which tracking requests a page sends (GA4, Google Ads, Meta Pixel, TikTok Pixel, Google Tag Manager and other analytics, advertising and marketing tags), whether they respect the visitor's consent choice, and whether campaign attribution survives the visit. It shows this in a popup and a Chrome DevTools panel and can export it as a PDF.
```

**Permission justifications**

| Permission | Justification to paste |
|---|---|
| `activeTab` | When the user clicks the Hitline icon, Hitline reads the current tab once to list the tracking requests it sent. Without a click it has no access to any tab. |
| `scripting` | Runs one read-only function in the active tab (after the user clicks the icon) that returns the page's resource URLs, dataLayer consent commands, Google Tag Manager container ids, which known tracking tools are loaded and the names of tracking cookies. While the popup stays open it repeats this every 2 seconds on the same tab. Nothing is changed and nothing is sent. |
| `storage` | Saves the user's settings in chrome.storage.local on their computer: interface language, the domains they mark as their own site, tracking plan files they load and custom platforms they add (a name and a URL text). When the user clicks "Show in DevTools" in the popup, a short note of which event to show is kept in chrome.storage.session (memory only) until the DevTools panel reads it. Nothing else is stored. |
| DevTools page (`devtools_page`, not a permission) | Adds the Hitline tab to Chrome DevTools. Chrome gives it the inspected tab's network requests only while DevTools is open. |
| Host permissions | None requested. |

**Remote code**

```
No, I am not using remote code.
```

Hitline loads no scripts, fonts or data from the network. All code and fonts are in the package.

**Data usage**

Tick nothing in "What user data do you plan to collect". Hitline collects none of: personally identifiable information, health, financial, authentication, personal communications, location, web history, user activity or website content. Page data is analyzed in memory in the browser and never leaves it.

Tick all three certifications:

- I do not sell or transfer user data to third parties, outside of the approved use cases
- I do not use or transfer user data for purposes that are unrelated to my item's single purpose
- I do not use or transfer user data to determine creditworthiness or for lending purposes

## After approval

Send the listing link (`https://chromewebstore.google.com/detail/...`) to the agent. It sets Hitline to `live` with that `storeUrl` in `apps/site/src/content/tools.json`, so every "Add to Chrome" button on getlineapps.com points to the listing.

## What changed in 1.2.1 (for the "What's new" note, optional)

```
The DevTools panel now fits any window: docked to the side, at the bottom or in a small window, nothing overlaps or scrolls sideways.
```

## What changed in 1.2.0 (for the "What's new" note, optional)

```
Clear loading steps in the popup and DevTools, events grouped in one card per page, and the popup now finds tags on busy pages it used to miss.
```

## What changed in 1.1.0 (for the "What's new" note, optional)

```
50 platforms instead of 6, custom platforms, newest events first with live highlights, GTM tags and events read from the container, data quality checks, a detailed audit PDF and a live popup.
```

The detailed description names platform groups and only a few platforms on purpose: the Web Store rejects long lists of brand names as keyword spam (see the Serpline rejection, commit cf9f136).
